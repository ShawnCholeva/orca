# Orca - Milestone 4: Embedded Sessions
## Principal Engineer Review and Simplified Execution Plan

**Status:** Ready for execution after scope cuts
**Scope:** Milestone 4 only
**Builds on:** M1 local daemon/event loop, M2 internal plugin/skill registries, M3 refined Goals and attached Workspaces
**Proof point:** A user opens a refined Goal, creates a manual session in an attached workspace, launches a shell or agent in an embedded PTY, interacts with it, stops it, and can reload session metadata plus a useful output tail after daemon restart.

Milestone 4 adds one new runtime capability: the daemon starts and manages local PTY processes. It must not become the memory engine, context assembler, workflow engine, adapter framework, or terminal multiplexer.

---

## 1. MVP Product Loop

```text
User opens a refined Goal with attached workspaces
  -> creates a manual session
  -> chooses a workspace and adapter
  -> optionally enters role and short instruction
  -> daemon validates Goal, workspace, and adapter id
  -> daemon commits session row and lifecycle event in one SQLite transaction
  -> daemon launches one PTY in the selected workspace
  -> adapter provides command, args, env, cwd only
  -> desktop renders one embedded xterm.js terminal
  -> user sends input and resize over the existing WebSocket
  -> daemon streams PTY output over the existing WebSocket
  -> daemon stores a capped output tail outside the general event store
  -> daemon records exit/stop/failure lifecycle events
  -> session metadata and output tail survive daemon restart
```

Everything else is deferred.

## 2. Review Findings: Overengineering To Remove

### Adapter/plugin invocation APIs

Reject generic `POST /v1/adapters/:id/invoke`, generic plugin execution, adapter hooks, adapter output transformers, adapter-owned PTY behavior, adapter-owned streaming, and adapter-specific summaries.

Why premature: M4 has exactly one invocation shape: start a PTY-backed session. A generic adapter invocation API would add a second execution surface before the first one is proven. Future external plugin loading can reuse the internal spawn contract later; M4 does not need public extensibility.

Deferred owner: external plugin ecosystem / Level 4+, not M4.

### Session orchestration beyond create/start/stop

Reject workflow engines, task assignment, recommendations, auto-launching, cross-Goal global session management, and session scheduling.

Why premature: M4 sessions are user-started terminal sessions. There is no task graph, shared memory, or recommendation engine yet. Anything beyond create/list/detail/start/stop is orchestration without inputs.

Deferred owner: recommendations/task graph in later MVP milestones; supervised execution in Level 4.

### Context package injection and role catalogs

Keep `role` and `instruction` as opaque persisted strings. Do not add role catalogs, role plugins, context packages, prompt assembly, memory references, or automatic prompt construction.

Why premature: M4 proves PTY execution, not context assembly. Treating role/instruction as structured context would create schema and UX commitments before M5/M6 define memory and context.

Deferred owner: M5 shared memory and M6 context assembly.

### Terminal abstractions

Reject tabs, panes, terminal sharing, replay engines, transcript export, terminal search, command palettes, custom themes, custom keymaps, binary WebSocket migration, tmux/screen integration, and process re-parenting.

Why premature: M4 needs one terminal view attached to one PTY. xterm.js already provides the terminal behavior needed for MVP interaction. Re-parenting and replay fundamentally change lifecycle semantics.

Deferred owner: future terminal UX milestone after real usage demands it.

### Output as event stream

Reject `session.output.received`, `session.input.sent`, and `session.resized` domain events.

Why premature: output, input, and resize are high-volume transport signals. Persisting them in the general event store would pollute the orchestration event log and create privacy and growth risk.

Deferred owner: M5 may read output chunks for extraction, but M4 should not create memory or transcript analytics.

### Adapter configuration UI

Reject adapter settings screens, per-workspace command environments, CLI flag builders, and marketplace loading.

Why premature: hardcoded adapter defaults plus env-var overrides are enough to prove command resolution. Configuration UI adds product complexity before the commands have been exercised.

Deferred owner: adapter UX milestone after M4 usage validates which settings matter.

### Packaging and protocol rewrites

Reject new sockets, binary WS protocol, external queues, storage provider abstractions, and background worker pools.

Why premature: the existing JSON WebSocket and synchronous SQLite loop can prove M4. Rewriting transport or storage before measuring real terminal throughput optimizes for hypothetical scale.

Deferred owner: future performance milestone if measurements show the JSON channel or SQLite writes are the bottleneck.

## 3. Simplification Decisions

### Keep adapters internal and spawn-only

Adapters are daemon-local modules that return `{ command, args, env, cwd }`. They do not touch DB, events, PTY handles, streaming, output, summaries, memory, or prompts.

MVP velocity: small files, easy tests, no orchestration framework.

Future safety: the spawn contract is a stable seam for later plugin loading.

### Hardcode adapter defaults

Support:

- shell/manual: `ORCA_SHELL` -> `$SHELL` -> `/bin/zsh` -> `/bin/bash` -> `/bin/sh`; Windows best effort: `ORCA_SHELL` -> `%COMSPEC%` -> `cmd.exe`.
- Claude Code: `ORCA_CLAUDE_CODE_BIN` -> `claude`.
- opencode: `ORCA_OPENCODE_BIN` -> `opencode`.
- codex: `ORCA_CODEX_BIN` -> `codex`.

No CLI-specific flags in M4.

MVP velocity: deterministic implementation, clear command-not-found behavior.

Future safety: env-var overrides do not block later persisted adapter config.

### Use the existing WebSocket

Use JSON frames with base64 payloads for terminal bytes. Do not add binary frames in M4.

MVP velocity: reuses M1 transport, auth, and connection behavior.

Future safety: binary frames can be added later behind the same `session.output` concept if measured output volume requires it.

### Use projection reads, not replay utilities

`GET /v1/goals/:id/sessions` and `GET /v1/sessions/:id` read tables directly. Events remain lifecycle signals and UI refresh triggers.

MVP velocity: avoids event replay machinery.

Future safety: M5 can subscribe to terminal lifecycle events and read output chunks.

### Make sidecar feasibility an early gate

Before broad session work, verify `node-pty` installs, imports, spawns a trivial process, and can be copied into the sidecar runtime tree.

MVP velocity: finds native-module blockers before domain/UI work stacks on top.

Future safety: keeps the packaging boundary explicit and limits `node-pty` imports to one module.

### Archive is optional for the proof

Archive is cheap but not required to prove embedded sessions. Keep it only if it stays a single status transition and one endpoint. Drop it if it delays shell/manual full-loop validation.

MVP velocity: prevents cleanup UX from blocking the runtime proof.

Future safety: archived status can be added later without breaking create/start/stop.

## 4. Execution Risks And Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| `node-pty` native install or prebuild unavailable for a target triple | Can block M4 shipping and Tauri sidecar packaging | First executable task verifies install/import/spawn and sidecar dry-run. Do not build broader session code until this passes for the supported M4 targets. |
| Native import leaks outside PTY wrapper | Sidecar, tests, and platform handling become scattered | Only `apps/daemon/src/pty/manager.ts` imports `node-pty`; usecases depend on local `PtyManager` interface and fake. |
| Sidecar dev mode differs from bundled mode | Works in `tsx`, fails in Tauri bundle | Add a minimal sidecar smoke that requires `node-pty` and spawns/terminates a shell before desktop UI polish. |
| Session event and row update split across transactions | UI sees events that do not match projections after crash | Every lifecycle transition inserts event and updates `sessions` in one SQLite transaction; broadcast only after commit. |
| Output bytes written to general event store | Event table growth and privacy risk | Output goes only to `session_output_chunks`; input and resize are not persisted. |
| Output ordering gaps or duplicate replay | Terminal duplicate output or missing bytes on reconnect | Store per-session `seq` and byte offsets. Client tracks last seen seq; on gap, reload detail tail once. |
| SQLite growth from output | Local DB bloat and slow backups | Enforce per-session tail cap, default 1 MiB. Delete whole oldest chunks; no transcript system in M4. |
| Secrets in output or logs | Persistent credential exposure | Never log output or instruction text. Keep output bearer-auth-gated and local. Document retention behavior. |
| Base64 overhead on JSON WS | More bytes and CPU under high output | Accept for MVP; coalesce chunks. Drop slow subscribers and let UI refetch tail. |
| Slow WebSocket consumer | Daemon memory growth | If buffered amount exceeds a blunt threshold, close that subscriber. Do not block PTY or DB writes. |
| Adapter command not found | User cannot start intended adapter | Lazy availability on `GET /v1/adapters`; start records `session.failed` with `command_not_found` and returns 422 with env-var override hint. |
| argv shell quoting bugs | Injection and broken commands | Adapters return `command` plus `args[]`; no shell strings. Role/instruction are env vars only for shell/manual. |
| Workspace deleted, detached, or unreadable | PTY starts in wrong or missing cwd | Revalidate workspace belongs to Goal and `fs.access` succeeds at create and again at start. Existing sessions stay visible. |
| Archived Goal session creation | New execution under inactive Goal | `POST /v1/goals/:id/sessions` rejects archived Goals. Existing sessions remain readable. |
| Running sessions on daemon restart | UI lies about live process | Boot reconciliation runs before HTTP/WS listen and marks `starting`/`running` as `failed` with `daemon_restart`. No process resumption. |
| Stop races with natural PTY exit | Double terminal event or wrong status | Runtime tracks `stopRequested`; exactly one terminal lifecycle event is committed. |
| xterm mount/unmount leaks | Duplicate input handlers or stale WS subscriptions | `SessionTerminalView` owns one terminal and one subscription; dispose xterm, fit addon, resize observer, and unsubscribe on unmount. |
| Resize loops | UI churn and WS spam | Debounce resize; only send when cols/rows change. |
| Desktop reconnect stale subscription | Missing live frames after network blip | On reconnect, refetch session detail tail, reset last seen seq, then send `session.subscribe`. |
| M1/M2/M3 regressions | Existing product loop breaks | Baseline typecheck/test before M4; run targeted regression tests at each integration checkpoint. |

## 5. Milestone Boundary

### Required foundations in M4

- Session identity scoped to Goal and Workspace.
- Lifecycle events for create/start/exit/fail/stop.
- Capped persisted output tail for later M5 extraction.
- Internal adapter descriptors from the M2 plugin registry.
- PTY wrapper with fake implementation for tests.
- Existing HTTP + WebSocket channel extended for session lifecycle and terminal traffic.

### Acceptable future-facing seams

- `role` and `instruction` fields stored as opaque text.
- Adapter registry internal to daemon, backed by M2 plugin descriptors.
- Output chunks with sequence and byte offsets.
- Lifecycle events sufficient for M5 to know a session finished.

### Deferred systems

- M5: shared memory, memory extraction, session summaries, decision extraction.
- M6: context assembly, prompt packages, context injection.
- Later MVP/Level 4: tasks, recommendations, workflow engine, supervised execution, auto-launch.
- Level 5: autonomous recovery, distributed/multi-goal orchestration, strategic planning.
- Packaging future: signed production distribution and expanded target matrix.

Add the minimum lifecycle events:

```text
session.created
session.started
session.exited
session.failed
session.stopped
```

Optional if archive remains:

```text

```

Recommended payloads stay small:

- `session.created`: `sessionId`, `goalId`, `workspaceId`, `adapterId`.
- `session.started`: `sessionId`, `goalId`, `pid`, `cwd`, `terminalCols`, `terminalRows`.
- `session.exited`: `sessionId`, `goalId`, `exitCode`, `exitSignal`.
- `session.failed`: `sessionId`, `goalId`, `failureReason`, `failureDetail`.
- `session.stopped`: `sessionId`, `goalId`, `exitCode`, `exitSignal`, `reason: "user_request"`.
- `session.archived`: `sessionId`, `goalId`.

Do not add:

- `session.output.received`
- `session.input.sent`
- `session.resized`
- memory events
- summary events
- context events
- task events
- recommendation events
- workspace refresh/scan/index events
- adapter hook events
- workflow events

All lifecycle events and projection writes happen in the same SQLite transaction. Broadcast only committed events.

## 10. Database And Persistence

Keep M4 to two tables.

```sql
CREATE TABLE sessions (
  id TEXT PRIMARY KEY,
  goal_id TEXT NOT NULL,
  workspace_id TEXT NOT NULL,
  adapter_id TEXT NOT NULL,
  role TEXT,
  instruction TEXT,
  title TEXT NOT NULL,
  status TEXT NOT NULL,
  pid INTEGER,
  command TEXT,
  args_json TEXT,
  cwd TEXT,
  terminal_cols INTEGER,
  terminal_rows INTEGER,
  exit_code INTEGER,
  exit_signal TEXT,
  failure_reason TEXT,
  failure_detail TEXT,
  created_at TEXT NOT NULL,
  started_at TEXT,
  exited_at TEXT,
  archived_at TEXT,
  output_seq INTEGER NOT NULL DEFAULT 0,
  output_bytes_kept INTEGER NOT NULL DEFAULT 0,
  output_offset_first INTEGER NOT NULL DEFAULT 0,
  FOREIGN KEY (goal_id) REFERENCES goals(id) ON DELETE CASCADE,
  FOREIGN KEY (workspace_id) REFERENCES workspaces(id) ON DELETE RESTRICT
);

CREATE INDEX idx_sessions_goal_created
  ON sessions(goal_id, created_at DESC);

CREATE INDEX idx_sessions_goal_status
  ON sessions(goal_id, status);

CREATE TABLE session_output_chunks (
  session_id TEXT NOT NULL,
  seq INTEGER NOT NULL,
  byte_offset INTEGER NOT NULL,
  byte_length INTEGER NOT NULL,
  written_at TEXT NOT NULL,
  data BLOB NOT NULL,
  PRIMARY KEY (session_id, seq),
  FOREIGN KEY (session_id) REFERENCES sessions(id) ON DELETE CASCADE
);

CREATE INDEX idx_session_output_session_seq
  ON session_output_chunks(session_id, seq);
```

Fields to avoid in M4:

- memory extraction state
- summary status
- context bundle id
- task id
- recommendation id
- workflow id
- role catalog id
- adapter config id
- pane/tab ids
- workspace scan/index metadata
- transcript analytics metadata

Persistence must support:

- list/detail after restart
- recent output tail after restart
- failed reconciliation for previously running sessions
- M1/M2/M3 create/list/restart compatibility

Retention:

- default per-session output tail cap: 1 MiB
- configurable with `ORCA_SESSION_OUTPUT_TAIL_BYTES`
- delete whole oldest chunks only
- no global retention, export, transcript, or analytics in M4

## 14. Revised Execution Sequence

The order below prioritizes early failure discovery and small executable slices.

### M4-000 - Baseline verification

Run M1/M2/M3 typecheck and tests before changing M4 code. Record any existing failures and do not mix regression fixes with session work unless they block M4.

Validation: `pnpm -r typecheck`, `pnpm -r test`.

### M4-001 - Native PTY feasibility and sidecar spike

Add or locally test `node-pty`, verify import and trivial spawn, then verify the sidecar runtime-copy approach can include it. This may be a scratch test before final code.

Validation:

- `node -e "require('node-pty')"` equivalent for the package setup.
- trivial PTY spawn exits cleanly.
- sidecar build script can locate/copy native artifact in principle.

Stop condition: if target prebuilds are unavailable, resolve packaging strategy before continuing.

### M4-002 - Contracts

Add minimal session, adapter, event, HTTP, and WS schemas in `packages/contracts`. Do not add internal PTY/adapter spawn types or future memory/context/task schemas.

Validation: contracts typecheck and fixture parse tests.

### M4-003 - Migration

Add `0003_sessions.sql` with only `sessions` and `session_output_chunks`. Verify fresh and upgraded DBs.

Validation: migration tests for fresh, M3-upgrade, idempotent replay, FKs, indexes.

### M4-004 - Adapter command resolver and adapters

Implement `resolveBinary`, shell/manual, Claude Code, opencode, codex, and internal adapter registry. Keep CLI args empty for agent CLIs.

Validation: PATH hit/miss, env override hit/miss, shell fallback, spawn shape tests.

### M4-005 - PTY wrapper with fake

Implement `pty/types.ts`, `pty/manager.ts`, and `pty/fake.ts`. Only this wrapper imports `node-pty`.

Validation: fake unit tests plus one guarded real-PTY smoke test.

### M4-006 - Session projection and create/list/detail without PTY start

Implement session row writes, per-Goal list, detail with empty output, and `session.created`. Wire HTTP:

- `POST /v1/goals/:goalId/sessions`
- `GET /v1/goals/:goalId/sessions`
- `GET /v1/sessions/:id`
- `GET /v1/adapters`

Validation: create/list/detail survive daemon restart before any PTY start exists.

### M4-007 - Output store and replay

Implement `appendChunk` and `readTail` with cap enforcement. Test independently using SQLite.

Validation: seq ordering, byte offsets, truncation, cap behavior, no event-store writes.

### M4-008 - Session start with fake PTY

Implement `POST /v1/sessions/:id/start` behind the fake PTY in usecase tests. Validate workspace and adapter resolution, commit `session.started`, wire fake output to output store, and mark fake exit.

Validation: create -> start -> output -> exit using fake PTY; command-not-found and workspace-unavailable failures persist `session.failed`.

### M4-009 - Stop and restart reconciliation

Implement stop semantics, stop-vs-exit race handling, and boot reconciliation before HTTP/WS listen.

Validation: SIGTERM -> SIGKILL behavior through fake PTY, exactly one terminal event, `running`/`starting` rows become `failed` with `daemon_restart` on boot.

### M4-010 - WebSocket terminal protocol

Add `session.subscribe`, `session.unsubscribe`, `session.input`, `session.resize`, `session.output`, and `session.error` on the existing WS channel.

Validation: subscribe receives output, unsubscribe stops output, input/resize reach fake PTY, unknown session returns error, slow consumer policy is deterministic.

### M4-011 - Real shell vertical slice

Run the full daemon loop with shell/manual and real `node-pty` before desktop work:

```text
create Goal/workspace
GET /v1/adapters
create session
start shell
subscribe WS
send "echo hello\n"
observe output
read persisted tail
stop session
restart daemon
list/detail session
```

Validation: one integration test plus manual daemon smoke.

### M4-012 - Desktop API and session panel

Add desktop client methods and the Goal detail Sessions panel with create dialog and session list. Use mocked API/WS tests first.

Validation: empty/list states, dialog validation, create/start flow, structured error display.

### M4-013 - Desktop terminal view

Add xterm.js terminal view. On mount, fetch detail tail, subscribe, write live output, forward input/resize, clean up on unmount.

Validation: component tests with mocked WS and manual shell session in Tauri/dev app.

### M4-014 - Agent adapters polish

After shell/manual works end to end, verify Claude Code, opencode, and codex command resolution and startup behavior where binaries are available. Missing binaries must fail clearly.

Validation: adapter availability display, command-not-found path, one real installed agent smoke if available.

### M4-015 - Sidecar packaging verification

Update the sidecar build script for `node-pty` and verify bundled runtime import/spawn.

Validation: `pnpm --filter @orca/daemon build:sidecar`; bundled daemon can require `node-pty` and spawn a trivial PTY on at least the M4-supported local target.

### M4-016 - Final regression and documentation

Run full typecheck/tests, record manual smoke, update README/operation notes with endpoints, WS messages, env vars, retention cap, and restart policy.

Validation: full automated suite plus manual shell full-loop.

## 17. Definition Of Done

M4 is done when:

1. A refined Goal detail view can create a session for an attached workspace.
2. The user can select shell/manual, Claude Code, opencode, or codex adapters; unavailable adapters are clear.
3. The daemon validates Goal, workspace, and adapter before start.
4. Session create/start/exit/fail/stop lifecycle transitions are persisted as domain events and projections in the same transaction.
5. The daemon broadcasts lifecycle events only after commit.
6. The daemon launches exactly one PTY per running session in the selected workspace.
7. The desktop renders one embedded xterm terminal for the selected session.
8. Input, resize, and output flow over the existing JSON WebSocket channel.
9. Input and resize are not persisted.
10. Output is not persisted in the general event store.
11. A capped output tail is stored in `session_output_chunks`.
12. Session list/detail and output tail survive daemon restart.
13. Sessions that were `starting` or `running` on daemon boot are marked `failed` with `daemon_restart` before HTTP/WS accepts traffic.
14. Stop sends SIGTERM, then SIGKILL after a short grace period.
15. Command-not-found produces a persisted `session.failed` and a clear 422 response.
16. Only the PTY wrapper imports `node-pty`.
17. Adapters are pure spawn factories and do not own PTY behavior.
18. `pnpm -r typecheck` and `pnpm -r test` pass, including M1/M2/M3 regressions and M4 shell/restart tests.
19. The sidecar build can include `node-pty` for the supported M4 target.
20. No memory extraction, summary extraction, context assembly, task graph, recommendation engine, workflow engine, file watcher/indexer, global sessions dashboard, adapter config UI, terminal multiplexer, process re-parenting, cloud/distributed runtime, or Level 4/5 automation has been added.

The milestone is successful when the shell/manual adapter proves the complete embedded-session operating loop. Agent adapter polish is valuable, but it must not delay that proof.
