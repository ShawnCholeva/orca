# Orca - Milestone 6: Context Assembly

## Principal Engineer Review and Simplified Execution Plan

**Status:** Planned  
**Scope:** Milestone 6 only  
**Builds on:** M1 daemon/event loop, M2 internal plugin/skill registries, M3 refined Goals and Workspaces, M4 PTY sessions, M5 Goal-scoped memory/decisions/session summaries  
**Proof point:** A user prepares context for a new Goal session, previews it, starts a normal M4-managed PTY session with that package attached, and can reload package metadata plus rendered context after daemon restart.

Milestone 6 adds one product foundation: durable, bounded, Goal-scoped context packages for session startup. It must not become recommendations, task generation, workflow execution, continuous reasoning, semantic search, provider/model configuration, prompt management, transcript analytics, or a generic skill invocation platform.

---

## 1. MVP Product Loop

```text
User opens a Goal and starts the new-session flow
  -> chooses adapter, workspace, role, and short session objective
  -> daemon reads bounded Goal/refinement/workspace/memory/decision/summary projections
  -> daemon runs one internal session-preparation job boundary
  -> deterministic assembler produces compact role-aware sections
  -> daemon validates, redacts, caps, and persists package + assembly events atomically
  -> daemon broadcasts committed events with ids and small metadata only
  -> desktop shows context preview, source counts, status, warnings, and retry/regenerate
  -> user starts a normal M4 PTY session with contextPackageId
  -> adapter receives context through an explicit adapter-safe path or declares preview-only
  -> session row stores contextPackageId
  -> package, assembly metadata, and session association survive daemon restart
```

Everything else is deferred.

## 2. Review Findings: Overengineering To Remove

### Generic skill invocation APIs

Reject public skill invocation routes, generic skill payloads, skill schedulers, public context-builder invocation, and any `/skills/:id/invoke` style API.

Why premature: M6 has one internal skill-shaped job: session preparation. A public invocation API commits Orca to plugin execution semantics before the deterministic context loop has shipped.

Simpler path: register one internal `orca/session-preparation` descriptor for M2 diagnostics, but call it only from daemon context use cases.

Future owner: external plugin ecosystem and Level 4/5 execution, after the internal shape proves useful.

### Generic context-builder and prompt frameworks

Reject context-builder registries, prompt-injection frameworks, prompt template libraries, prompt experiments, role policy systems, and generic adapter prompt routing.

Why premature: there is one context product loop and one output shape: startup context for a Goal session. A framework would add abstraction before there are two real call sites.

Simpler path: one daemon-local assembler interface, one deterministic implementation, and a small renderer.

Future owner: M7 only if recommendations need a separate context reader; post-MVP if prompt experimentation becomes a product need.

### AI/model/provider integration

Reject model SDKs, provider config UI, key storage, model selection, raw prompt persistence, raw model response persistence, and provider retry/cost accounting.

Why premature: provider integration brings latency, secrets, billing, error semantics, redaction, and logging risk. None of it is required to prove deterministic context assembly from existing projections.

Simpler path: deterministic selection and rendering. Keep the assembler interface as the later plugin seam.

Future owner: post-M6 AI-backed assembler plugin, not core M6.

### Background queues, workers, schedulers, workflow engines

Reject worker pools, background queues, schedulers, workflow engines, distributed job state, and automatic retries.

Why premature: this is a local-first daemon with one SQLite database. M6 assembly is bounded projection reads plus pure functions and should complete inside one HTTP request.

Simpler path: create a `context_assemblies` row, run assembly in-process, commit success/failure in one transaction. Retry is an explicit POST.

Future owner: performance work only if measured local usage requires it.

### Recommendation, task, graph, and autonomy systems

Reject recommendation generation, task/work-unit generation, validation recommendations, conflict detection, decision impact analysis, workflow automation, supervised execution, automatic session launch, autonomous approvals, agent coordination, and continuous daemon reasoning.

Why premature: M6 should produce context that future systems can read. It should not decide what to do next.

Simpler path: confirmation-required decisions are labeled in rendered context; no action is taken.

Future owner: M7 recommendations; Level 4 supervised execution; Level 5 autonomy.

### Semantic memory and cross-Goal systems

Reject semantic ranking, embeddings, vector databases, workspace indexing, file watching, knowledge graphs, cross-Goal memory, memory consolidation, aging/decay, and global search.

Why premature: M5 already provides enough Goal-scoped projections to prove the startup context loop. Cross-Goal or semantic systems introduce privacy and relevance problems before one-Goal behavior is validated.

Simpler path: deterministic selection by status, type, confidence, confirmation requirement, recency, and role.

Future owner: post-MVP learning/search work.

### Transcript analytics

Reject full transcript processing, transcript replay, transcript analytics, raw terminal output events, and reading M4 output tails during M6 assembly.

Why premature: M4 output tails are runtime evidence for M5 extraction, not startup context. They are noisy, large, and may contain secrets.

Simpler path: read only M5 `session_summaries`; never import the output-tail module from context assembly code.

Future owner: future terminal/history work only after retention and privacy rules are explicit.

### UI command-center growth

Reject global context dashboards, recommendation panels, task panels, workflow UI, command centers, autonomy controls, provider/model settings, analytics, diff views, package history pages, and prompt package editors.

Why premature: M6 needs a new-session preview/status surface inside Goal detail. A command center implies systems that do not exist yet.

Simpler path: role/objective controls, preview, source summary, status, retry/regenerate, and session badge.

Future owner: later UX after M6/M7 data proves which views matter.

|---|---|---|---|
| Session preparation skill/job | Keep internal-only | Gives a testable boundary without public execution API | Plugin-backed assembler can replace the implementation later |
| Role-aware context | Keep small enum | Proves context differs by session intent without role config | Add roles later as contract bump |

| Adapter-aware delivery | Keep explicit per existing adapter | Avoids unsafe generic prompt injection | Adapter ecosystem can add capabilities later |
| Goal memory selection | Keep deterministic | Required proof input; cheap and testable | Semantic ranking deferred post-MVP |
| Decision selection | Keep deterministic | Required proof input; confirmation handling is high value | Decision impact/conflict analysis deferred M7+ |
| Confirmed decisions | Keep | Settled facts are useful context | No future cost |
| Proposed decisions | Keep only when confirmation-required or budget allows | Prevents silent over-injection | M7 can reason over proposed decisions |
| Confirmation-required decisions | Keep pinned and labeled | Avoids treating unresolved choices as settled | Level 4 can later gate actions on them |
| Sibling session summaries | Keep from M5 summaries only | High value, no transcript processing | Transcript analytics deferred |
| Current refinement fields | Keep | Canonical Goal intent source | No future cost |
| Workspace metadata | Keep existing attached metadata only | Gives cwd/branch context without scanning | Workspace indexing deferred |
| Lazy workspace/git inspection | Reuse M3 only | Avoids new git/file IO in M6 | Deeper inspection deferred |
| Session objective input | Keep capped free text | Gives user control over this package | Structured tasks deferred M7 |
| Context preview before launch | Keep | Builds trust and debuggability | Editable previews deferred |
| Context status on sessions | Keep small badge | Makes session association visible | History/diff UI deferred |
| Manual regenerate | Keep through create endpoint with `replacePackageId` | One route covers first create and regenerate | Dedicated regenerate endpoint can be added later |
| Retry failed assembly | Keep through same create endpoint | No queue/retry subsystem | Background retry deferred |
| Context persistence | Keep | Exit criterion | No future cost |
| Context lifecycle events | Keep minimal | Enables live refresh and audit | More events only when consumers exist |
| Context idempotency | Keep | Prevents duplicate packages on double click/retry | Same key supports future async runner |
| Source attribution | Keep compact JSON ids | Avoids a third table and copied source text | `context_package_sources` table can be added in M7 if source lookup becomes real |
| Byte/token-equivalent budgets | Keep | Hard cap plus understandable UI | Token-accurate accounting deferred |
| Deterministic assembler | Keep only assembler | Fast, local, testable, no provider risk | AI assembler plugin later |
| Redaction | Keep best-effort | Reduces persistence and delivery leakage | Stronger policy/governance deferred |
| Prompt delivery | Keep adapter-specific | Safer than generic injection | Prompt framework deferred |
| User-editable context | Defer | Editing breaks lineage and adds UI/state complexity | Later UX milestone |
| Context diffing/history | Defer | Not needed for first proof | Later UX/debug milestone |
| Automatic session launch after assembly | Reject | Session creation remains user-driven | Level 4/5 only |
| Recommendations/tasks/workflows/conflicts | Reject | Would turn context into action planning | M7 / Level 4 |
| Provider/model configuration | Reject | No AI calls in M6 | Post-M6 plugin |
| Cross-Goal memory/search/indexing/embeddings | Reject | Not needed and high leakage risk | Post-MVP |

## 4. Simplified Architecture

```text
Tauri Desktop
  Goal detail new-session flow
    - adapter/workspace/role/objective
    - Prepare context
    - preview/status/source summary
    - Start session with contextPackageId

  POST /v1/goals/:goalId/context-packages
  GET  /v1/goals/:goalId/context-packages
  GET  /v1/context-packages/:id

  context.package.created

```

M6 has no new top-level packages, no public skill invocation, no queue, no worker, no provider SDK, no source-index table, no workspace scanner, and no recommendation reader.

## 5. Runtime Flows

### Prepare Context

```text
1. UI sends POST /v1/goals/:goalId/context-packages
   { adapterId, workspaceId?, role, objective, replacePackageId? }
2. Daemon validates request with zod.
3. Daemon builds bounded candidate input from Goal/refinement/workspace/memory/decision/session_summary projections.
4. Daemon computes source fingerprint from:
   goal id, latest refinement id/version, workspace id,
   bounded candidate M5 source ids + updated_at/content hashes where available,
   role, adapter id, objective hash, assembler version.
5. If an active package with the same fingerprint exists, return it without new events.
6. Insert context_assemblies row as `pending`.
7. Run deterministic assembler.
8. Validate assembler output with zod.
9. Normalize, redact, cap, estimate tokens, and render.
10. Commit in one SQLite transaction:
    - context_packages row
    - context_assemblies -> succeeded + package_id
    - context.assembly.requested
    - context.assembly.completed
    - context.package.created
11. Broadcast events only after commit.
12. UI refetches package detail and displays preview.
```

Failed assembly commits the assembly row and `context.assembly.failed` in one transaction. Failed assemblies do not create package rows.

### Start Session With Context

```text
1. UI sends POST /v1/sessions with existing M4 fields + contextPackageId.
2. Daemon verifies package belongs to the same Goal, is usable, and matches adapter/workspace where relevant.
3. Daemon creates the normal M4 session row with sessions.context_package_id.
4. Adapter startup reads the package and delivers context through its declared safe path.
5. Existing M4 PTY lifecycle, input, resize, output tail, and restart behavior continue unchanged.
6. session.created includes contextPackageId.
```

M6 deliberately does not support inline `assembleContext` inside `POST /v1/sessions`. The two-step prepare-then-start flow is easier to debug, gives the user a real preview, and avoids complex partial failure behavior.

### Regenerate Or Retry

Regenerate is the same create endpoint with `replacePackageId`. The new package references `supersedes_package_id`; the old package is not mutated in M6.

Retry after failure is the same create endpoint with the same request. Failed assemblies are terminal and excluded from active idempotency, so retry creates a new assembly row.

No automatic retry, backoff, queue, or scheduler.

### Restart Reconciliation

On daemon boot, before HTTP starts:

- mark `context_assemblies` in `pending` or `running` as `failed` with `failure_code='daemon_restart'`;
- append `context.assembly.failed` events in the same transaction as those updates;
- leave committed `context_packages` untouched;
- keep `sessions.context_package_id` associations intact.

### `packages/contracts`

Keep only shared wire schemas:

- `ContextPackage`, `ContextAssembly`, `ContextSourceRef`.
- `ContextRole`, `ContextPackageStatus`, `ContextAssemblyStatus`, `ContextAssemblyFailureCode`.
- create/list/detail response schemas.
- M6 event type literals.
- `CreateSessionRequest` extension for optional `contextPackageId`.

Do not add provider, prompt, task, recommendation, workflow, embedding, vector, role-policy, or generic skill invocation schemas.

### `apps/daemon/src/context`

Create a small daemon-local module:

- `input.ts` - bounded Goal/refinement/workspace/memory/decision/summary reads.
- `selection.ts` - pure deterministic selection functions.
- `assembler.ts` - `SessionPreparationAssembler` interface, deterministic implementation, fake for tests.
- `renderer.ts` - sectioned plaintext and adapter framing helpers.
- `usecases.ts` - create/read/regenerate/idempotency/transaction orchestration.
- `routes.ts` - HTTP handlers, if route code is already split this way.
- `reconcile.ts` - stale assembly reconciliation.

Do not create a generic builder framework, pipeline directory, provider directory, prompt store, queue runner, worker pool, or multiple production assemblers.

### `apps/daemon/src/sessions`

Modify only the session create/read path:

- accept optional `contextPackageId`;
- validate same Goal and package usability;
- store `sessions.context_package_id`;
- include `contextPackageId` in session read responses and `session.created`.

Do not add `assembleContext` to session create in M6. Do not change PTY streaming, output tails, resize, stop, restart reconciliation, or terminal events beyond carrying the optional id.

### `apps/daemon/src/adapters`

Add explicit context delivery metadata to existing adapter descriptors, but keep it narrow:

```ts
interface AdapterContextDelivery {
  mode: 'initial_input' | 'context_file' | 'preview_only';
  maxBytes: number;
}
```

Implementation rules:

- `initial_input` writes to PTY stdin only for adapters where that is intentionally visible to the user, such as shell/manual.
- `context_file` writes rendered context to a session-scoped file with mode `0600`; the adapter may receive only the file path through its already-verified startup mechanism.
- `preview_only` means the UI shows context but the adapter is not auto-injected.

Do not invent or document unverified CLI flags for Claude Code, opencode, or codex. Each adapter must either use an existing verified M4 startup surface or declare `preview_only` for M6.

### `apps/daemon/src/skills`

Register one internal descriptor:

```ts
{
  id: 'orca/session-preparation',
  version: '0.1.0',
  category: 'internal',
  invocation: 'daemon-internal'
}
```

No public skill route. No generic invocation engine.

### `apps/daemon/src/server.ts`

Register the three M6 context routes and extend existing session routes. Use existing WebSocket broadcast behavior; no WebSocket commands.

### `apps/desktop/src/goal-detail`

Keep changes inside the existing Goal detail session creation area:

- role/objective controls;
- prepare/skip buttons;
- context preview/status panel;
- source summary by type;
- retry/regenerate action;
- session row context badge.

Do not add top-level routes, dashboards, command center UI, recommendation/task panels, provider settings, analytics, edit-context UI, diff UI, or package history pages.

### Tests

Keep test boundaries clear:

- contracts parse/reject tests;
- daemon migration/projection/usecase tests;
- input/selection/assembler/renderer pure tests;
- daemon HTTP tests for create/list/detail/session attach;
- adapter delivery tests using M4 fakes;
- restart reconciliation tests with file-backed SQLite;
- desktop component tests for prepare/preview/error/truncated/session badge states.

## 7. API Surface Reduction

### Keep

#### `POST /v1/goals/:goalId/context-packages`

Creates a package, retries a failed equivalent request, or regenerates from an existing package.

Request:

```json
{
  "adapterId": "claude-code",
  "workspaceId": "ws_123",
  "role": "engineer",
  "objective": "Implement the context input builder",
  "replacePackageId": "ctx_old_optional"
}
```

Response:

```json
{
  "package": { "...": "ContextPackage" },
  "assembly": { "...": "ContextAssembly" },
  "reused": false
}
```

For deterministic M6, this returns 200/201 synchronously. A future async assembler can return 202 without changing the route.

#### `GET /v1/goals/:goalId/context-packages`

Lists recent packages and recent assemblies for a Goal. This supports reload after restart and lets the UI show failed/pending/running states without a separate assembly endpoint.

Filters should be minimal: `sessionId`, `adapterId`, `limit`. No complex ranking, search, or source filtering.

#### `GET /v1/context-packages/:id`

Returns one package with rendered context and compact source refs. This powers preview and session context display.

#### `POST /v1/sessions` extension

Adds optional `contextPackageId` to the existing M4 request. Neither field present preserves M4 behavior.

### Defer

- `POST /v1/context-packages/:id/regenerate`: fold into the create route with `replacePackageId`.
- `GET /v1/sessions/:sessionId/context`: session detail already returns `contextPackageId`; UI can call `GET /v1/context-packages/:id`.
- `assembleContext` inside `POST /v1/sessions`: defer until context preparation is reliable and preview semantics are settled.
- archive/update endpoints for packages: package rows are immutable in M6; regenerate creates a new row.

### Reject

No endpoints for generic skills, generic context builders, prompt injection, workflow execution, recommendations, tasks, conflicts, embeddings/vector search, provider/model configuration, cross-Goal memory, transcript replay, or WebSocket context commands.

- raw assembler input/output events.
- raw prompt/model response events.
- prompt injection framework events.
- task, recommendation, workflow, conflict, embedding, indexing, cross-Goal, continuous reasoning, or agent coordination events.

All event writes happen in the same SQLite transaction as projection updates. Broadcast only after commit. Serialized payloads should stay under 4 KiB.

## 9. Database And Persistence

Milestone 6 can stay limited to two new tables plus one session column. Source attribution is stored as compact JSON on `context_packages`; do not add a `context_package_sources` table until a future milestone needs source reverse lookup at scale.

### `context_packages`

```sql
CREATE TABLE context_packages (
  id                    TEXT PRIMARY KEY,
  goal_id               TEXT NOT NULL REFERENCES goals(id),
  supersedes_package_id TEXT REFERENCES context_packages(id),
  adapter_id            TEXT NOT NULL,
  workspace_id          TEXT REFERENCES workspaces(id),
  role                  TEXT NOT NULL,
  objective             TEXT NOT NULL,
  status                TEXT NOT NULL CHECK (status IN ('ready')),
  rendered_context      TEXT NOT NULL,
  rendered_bytes        INTEGER NOT NULL,
  estimated_tokens      INTEGER NOT NULL,
  truncated             INTEGER NOT NULL DEFAULT 0,
  sparse                INTEGER NOT NULL DEFAULT 0,
  source_count          INTEGER NOT NULL,
  sources_json          TEXT NOT NULL,
  warnings_json         TEXT NOT NULL DEFAULT '[]',
  source_fingerprint    TEXT NOT NULL,
  assembler_version     TEXT NOT NULL,
  created_at            TEXT NOT NULL
);

CREATE INDEX idx_context_packages_goal_created
  ON context_packages(goal_id, created_at DESC);

```

Session association is represented only by `sessions.context_package_id`. Package rows stay immutable after creation.

### `context_assemblies`

```sql
CREATE TABLE context_assemblies (
  id                   TEXT PRIMARY KEY,
  goal_id              TEXT NOT NULL REFERENCES goals(id),
  package_id           TEXT REFERENCES context_packages(id),
  replace_package_id   TEXT REFERENCES context_packages(id),
  adapter_id           TEXT NOT NULL,
  workspace_id         TEXT REFERENCES workspaces(id),
  role                 TEXT NOT NULL,
  objective_hash       TEXT NOT NULL,
  source_fingerprint   TEXT NOT NULL,
  assembler_version    TEXT NOT NULL,
  request_fingerprint  TEXT NOT NULL,
  status               TEXT NOT NULL CHECK (status IN ('pending','running','succeeded','failed')),
  trigger              TEXT NOT NULL CHECK (trigger IN ('prepare','regenerate','retry')),
  failure_code         TEXT,
  failure_message      TEXT,
  requested_at         TEXT NOT NULL,
  started_at           TEXT,
  finished_at          TEXT
);

CREATE UNIQUE INDEX idx_context_assemblies_active_fingerprint
  ON context_assemblies(goal_id, request_fingerprint)
  WHERE status IN ('pending','running','succeeded');

CREATE INDEX idx_context_assemblies_goal_requested
  ON context_assemblies(goal_id, requested_at DESC);

CREATE INDEX idx_context_assemblies_status_requested
  ON context_assemblies(status, requested_at);
```

### Existing table change

```sql
ALTER TABLE sessions ADD COLUMN context_package_id TEXT REFERENCES context_packages(id);

CREATE INDEX idx_sessions_context_package
  ON sessions(context_package_id)
  WHERE context_package_id IS NOT NULL;
```

### Source JSON

`sources_json` is an array of compact refs:

```json
[
  {
    "type": "memory_item",
    "id": "mem_123",
    "sourceSessionId": "sess_123",
    "label": "constraint",
    "reason": "required",
    "marker": "mem:mem_123"

]
```

Rules:

- no copied source body text;
- ids must refer to Goal/refinement/workspace/memory/decision/session_summary/session rows from the same Goal;
- rendered context may include short redacted snippets because the package is the snapshot, but events and source refs do not duplicate raw source content;
- UI resolves source details from existing M3/M5 endpoints when needed.

### Reject New Tables

No M6 tables for recommendations, tasks, workflows, conflicts, workspace scans, workspace indexing, cross-Goal memory, knowledge graphs, embeddings, vector indexes, provider configuration, prompt libraries, prompt experiments, memory ranking models, policy/governance, transcript replay, or source reverse indexes.

## 10. Session Preparation Job

### Boundary

```ts
interface SessionPreparationAssembler {
  readonly version: string;
  assemble(input: ContextAssemblyInput): Promise<ContextAssemblyOutput>;
}
```

M6 has one production implementation and one fake for tests. The interface is internal to the daemon.

### Input

The input builder reads only:

- Goal row;
- latest Goal refinement fields;
- attached workspace metadata already known from M3;
- M5 memory projection rows;
- M5 decision projection rows;
- M5 session summary rows for sibling sessions.

It must not:

- read raw M4 output tails;
- read full transcripts;
- scan workspaces;
- watch files;
- run git beyond reused M3 lazy metadata;
- fetch external data;
- read cross-Goal memory.

### Deterministic Selection Rules

Memory:

- include promoted constraints, success criteria, architecture notes, blockers, validation results, and assumptions first;
- include candidate items only when confidence is high enough and budget remains;
- exclude archived rows;
- order by type priority, recency, then id.

Decisions:

- include confirmation-required decisions first under `Needs confirmation`;
- include confirmed decisions next under `Confirmed`;
- include proposed decisions only if budget remains and label them `Proposed`;
- exclude archived rows.

Sibling summaries:

- include only M5 `session_summaries` from the same Goal;
- exclude archived sessions;
- cap by count and bytes;
- order most recent first.

Workspace/refinement:

- include current Goal objective, success criteria, constraints, and scope notes;
- include workspace display name/path, branch, and dirty flag only if already available cheaply;
- never list files.

### Output

```ts
interface ContextAssemblyOutput {
  sections: Array<{
    kind: 'objective' | 'refinement' | 'workspace' | 'memory' | 'decisions' | 'sibling_summaries' | 'notes';
    title: string;
    body: string;
    markers: string[];
  }>;
  sources: ContextSourceRef[];
  warnings: string[];
  truncated: boolean;
  sparse: boolean;
  estimatedTokens: number;
}
```

Validation before persistence:

- zod validates input sanity and output shape;
- every marker maps to one source ref;
- every source ref belongs to the Goal;
- archived sources are dropped or fail clearly when required;
- best-effort secret redaction runs before rendered context persistence and adapter delivery;
- hard byte cap is enforced after rendering;
- failure messages are capped and redacted.

### Budgets

Defaults:

- rendered context hard cap: 32 KiB;
- advisory token estimate: `Math.ceil(bytes / 4)`, default budget label 8000;
- objective cap: 4 KiB;
- per-section cap: 8 KiB;
- memory item count cap: 30;
- decision count cap: 20;
- sibling summary count cap: 5;
- failure message cap: 256 chars.

If confirmation-required decisions alone exceed the cap, fail with `output_too_large` rather than silently hiding them.

### Idempotency

`request_fingerprint = sha256(goal_id + adapter_id + role + objective_hash + workspace_id + source_fingerprint + assembler_version + replace_package_id?)`.

Duplicate active requests return the existing package/assembly. Failed rows are terminal and do not block retry.

### Failure Codes

- `invalid_input`
- `invalid_output`
- `output_too_large`
- `goal_archived`
- `source_missing`
- `delivery_unavailable`
- `internal_error`
- `daemon_restart`

No automatic retry. Retry is user-triggered.

## 11. Context Package Domain

M6 context packages are:

- Goal-scoped;
- immutable once created;
- optionally associated to one session;
- role/objective/adapter/workspace aware;
- source-attributed by compact ids;
- capped, redacted, and rendered as a snapshot;
- readable after restart.

M6 context packages are not:

- cross-Goal context;
- task graphs;
- recommendation inputs with actions attached;
- editable prompt packages;
- ranked context candidates;
- knowledge graph nodes;
- provider prompts;
- policy/governance records.

### Lifecycle

```text
assembly pending/running -> succeeded -> package ready
assembly pending/running -> failed
```

Package rows are `ready` only in M6. Regeneration creates a new package with `supersedes_package_id`; the old row remains immutable. Package archive/update/delete policies are deferred.

### Sparse And Truncated Context

- Sparse context succeeds when sources are thin; set `sparse=true` and include a short warning.
- Truncated context succeeds only when lower-priority material was dropped without hiding required decision warnings.
- `output_too_large` fails when required sections cannot fit.

## 12. Adapter And Session Startup

M6 keeps adapter delivery explicit and conservative.

| Adapter | M6 behavior |
|---|---|
| shell/manual | `initial_input` is allowed because the context is visible in the terminal and user-driven. |
| Claude Code | Use `context_file` only if the existing adapter has a verified safe startup path for a file reference; otherwise `preview_only`. |
| opencode | Same as Claude Code: verified `context_file` path or `preview_only`. |
| codex | Same as Claude Code: verified `context_file` path or `preview_only`. |

Rules:

- never pass rendered context bytes through process args;
- never pass rendered context bytes through environment variables;
- if a file path is used, store content under the daemon/session data directory with mode `0600`;
- clean temp files on session terminal state and best-effort on boot;
- if delivery fails before spawn, session creation fails and no session row is committed;
- if adapter is `preview_only`, session creation can proceed and UI clearly says the adapter did not auto-receive context;
- session creation remains user-driven.

Do not add a generic prompt injection framework, adapter marketplace routing, provider-specific optimization, hidden startup actions, automatic tool execution, multi-agent coordination, or automatic approval/launch behavior.

## 15. Execution Risks And Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Context reads unbounded or drift into transcript/output-tail access | Privacy, latency, token bloat | Input builder imports only projection readers; test proves no output-tail import; cap every source class |
| Rendered context leaks into events/logs | Privacy and event-store growth | Events contain ids/counts only; logger denylist; tests assert event payloads do not contain rendered text |
| Raw prompts/model responses get stored | Privacy and future provider coupling | No provider integration in M6; no prompt/response schema exists |
| Confirmation-required decisions get buried or truncated | Agents may treat unresolved choices as settled | Pin `Needs confirmation`; fail if required block cannot fit |
| Duplicate packages from double-click/regenerate | Confusing UI and DB growth | Active request fingerprint; regenerate uses `replacePackageId`; list shows latest first |
| Failed retry blocked by idempotency | User cannot recover | Failed assemblies excluded from active unique index |
| Source refs become stale after M5 rows change/archive | Preview hover may resolve to changed/missing row | Rendered context is canonical snapshot; UI shows "source archived/missing" when lookup fails |
| Adapter delivery leaks via argv/env | Secrets visible in process listings | Pass only file paths when needed; never content; mode `0600`; preview-only if no safe path |
| Adapter startup surface is guessed incorrectly | Context silently not delivered | Do not guess flags; require verified path or `preview_only`; test descriptor behavior |
| Delivery failure commits a broken session | Session exists without promised context | Validate delivery inputs before commit; if failure occurs after session commit, use the existing M4 failure lifecycle and show the package as still reusable |
| SQLite migration breaks M1-M5 DBs | Existing data inaccessible | Fresh and M5-upgrade migration tests before daemon code depends on tables |
| Events and projections split across transactions | UI sees rows that do not exist or stale state | Single transaction for row changes and event append; broadcast after commit |
| Restart leaves pending/running assemblies | UI stuck forever | Boot reconciliation marks terminal failure before HTTP starts |
| Desktop shows stale context after regenerate | User starts with wrong package | Refetch on `context.*` events; Start button uses selected package id from latest detail fetch |
| Database growth from many regenerations | Local DB grows | 32 KiB package cap; no source text duplication; retention/GC deferred until measured |
| M4 session regression | Existing PTY loop breaks | No-context session create path remains unchanged and is regression-tested |
| M5 memory/decision regression | Existing panels/extraction break | M6 reads M5 projections only; no writes to M5 rows |

## 17. Validation Strategy

### Baseline Regression

- Run full typecheck/test before M6 work.
- Re-run targeted M4 session tests after session create changes.
- Re-run targeted M5 memory/decision/summary tests after input builder integration.
- Final full regression.

### Contract And Migration

- Contracts parse valid package/assembly/source refs and reject invalid role/status/objective sizes.
- Migration applies to fresh DB and M5 fixture DB.
- M6 reads return empty lists on migrated M5 DB.

### Assembly Correctness

- Empty/sparse Goal succeeds with warnings.
- Memory selection respects status/type/confidence/recency/role.
- Decision selection pins confirmation-required items.
- Sibling summaries come only from `session_summaries`.
- Archived artifacts are excluded or fail clearly when required.
- Output-tail content never appears in rendered context unless it already exists in an M5 summary.

### Persistence And Events

- Success commits package, assembly, and events atomically.
- Failure commits assembly and failure event atomically.
- Broadcast happens after commit.
- Event payloads never include rendered context or raw source text.
- Duplicate active request returns existing row.
- Retry after failed assembly creates a new row.
- Restart reconciles stale assembly rows.

### Adapter Delivery

- shell/manual receives visible initial input.
- context-file adapters receive only file paths, not content, when verified.
- preview-only adapters are clearly represented in API/UI.
- argv/env/logs do not contain rendered context bytes.
- temp files use restrictive permissions where supported and are cleaned best-effort.

### Desktop

- Prepare/skip paths both work.
- Preview displays ready, sparse, truncated, failed, and loading states.
- Retry/regenerate refetches and updates selected package.
- Start session sends `contextPackageId`.
- Session badge reloads after daemon restart.

### Manual Proof Loop

1. Create a Goal, refine it, and attach a workspace.
2. Create or fixture M5 memory, decisions, and sibling summaries for that Goal.
3. Open new-session flow, choose adapter/workspace/role/objective.
4. Prepare context and verify preview sections, warnings, source counts, and budget.
5. Start session and verify M4 PTY behavior still works.
6. Verify delivery mode or preview-only status matches adapter descriptor.
7. Restart daemon.
8. Verify package and session association are still visible.

## 18. Revised Definition Of Done

Milestone 6 is done when:

1. Users can prepare a Goal-scoped context package before starting a session.
2. Packages are built only from bounded Goal, latest refinement, attached workspace metadata, M5 memory, M5 decisions, and M5 sibling session summaries.
3. No M6 context assembly code reads raw M4 output tails, full transcripts, workspace contents, file indexes, external data, cross-Goal memory, embeddings, or semantic search.
4. The deterministic assembler is the only production assembler.
5. Assembler input and output are zod-validated before persistence.
6. Rendered context is normalized, best-effort redacted, capped, and persisted in `context_packages`.
7. Source attribution is compact and id-based; no source text is duplicated in events or source refs.
8. Confirmation-required decisions are included prominently or assembly fails if they cannot fit.
9. Idempotency prevents duplicate active packages for the same Goal/objective/role/adapter/source fingerprint/assembler version.
10. Retry/regenerate is manual and does not require a queue, worker, scheduler, or automatic retry.
11. Events are minimal control-plane events and are committed in the same transaction as projection rows.
12. Broadcast happens only after commit.
13. Pending/running assemblies are reconciled to failed on daemon restart.
14. `POST /v1/sessions` accepts an optional `contextPackageId`; no-context session creation remains M4-compatible.
15. Adapter delivery is explicit, safe, and never passes rendered context bytes through argv/env.
16. Desktop shows prepare/preview/status/source summary/retry and session context badge inside Goal detail.
17. Context package metadata and rendered context survive daemon restart.
18. M1-M5 behavior remains green.
19. `pnpm -r typecheck` and `pnpm -r test` pass.
20. No recommendations, tasks, workflows, conflict detection, provider/model configuration, generic skill invocation, prompt-management platform, workspace indexing, semantic search, cross-Goal memory, continuous reasoning, automatic session launch, supervised execution, or autonomy has been implemented.

When these are true, M6 has proven the context assembly loop quickly and cleanly. M7 can consume context packages for recommendations without M6 having become the recommendation engine.
